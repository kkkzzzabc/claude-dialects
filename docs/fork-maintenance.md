## 원격·브랜치 역할

Codex 포크와 같은 원칙을 쓰되, 공식 릴리스가 없는 동안에는 선정한 upstream SHA를 기준으로 합니다.

| 이름 | 역할 | 규칙 |
| --- | --- | --- |
| `origin` | `kkkzzzabc/claude-dialects` | 개인 변경·정상 태그 보관. PR 대상 저장소를 명시 |
| `upstream` | `stefandevo/claude-dialects` | 조회·fetch용. 명시적 요청 없이 upstream으로 push하지 않음 |
| `main` | upstream 원본 보관 | 개인 변경을 커밋하지 않고 fast-forward로만 동기화 |
| `dialects/custom` | 개인용 통합 소스 | 최신 개인용 소스의 유일한 통합 브랜치. 기본 작업 폴더에서 체크아웃 |
| `dialects/feat/<목적>` | 기능·도구 변경 | `dialects/custom`에서 분기. 최초 이전은 `dialects/feat/trial-promotion` 제안 |
| `dialects/sync/YYYYMMDD` | upstream 갱신 검증 | 선정한 upstream SHA 또는 향후 릴리스에서 분기 |
| `dialects/plan/fork-maintenance` | 최초 운영안 논의 | 운영안 확정·통합 후 정리. 장기 개발 기준으로 사용하지 않음 |
| `personal-good-YYYYMMDD-NN` | 검증·설치 소스 고정 | 정상 동작 검증 후 생성. 이동·재사용하지 않음 |

GitHub 기본 브랜치는 `main`을 유지합니다. `dialects/custom`은 소스 통합 기준이며,
설치 검증 전에도 존재할 수 있으므로 브랜치 이름만으로 정상 설치를 판단하지 않습니다.
정상 태그와 설치 기록이 설치된 버전을 식별합니다.

목적이 다른 변경은 별도 커밋으로 나누고 `type: English summary` 형식을 사용합니다.
기능 브랜치는 검토 후 merge commit으로 통합하고 이력을 보존합니다.
공유한 장기 브랜치는 rebase하거나 강제 push하지 않습니다.
PR은 필요할 때 개인 포크의 `dialects/custom`을 명시적인 대상으로 합니다.
작업 시작 시 미커밋 변경·워크트리·브랜치의 후속 커밋을 확인하고,
다른 워크트리의 브랜치를 강제로 체크아웃하지 않습니다.

## 임시 작업의 이전 범위

운영안 확정 후 작업 브랜치에서 다음 변경을 각각 검토하고 이전합니다.

1. GPT-6.1 지원: CLIProxyAPI v7.3.20의 Codex team/plus/pro 카탈로그 추가분을 패치로 정리합니다.
   다른 프록시 코드·free 목록은 변경하지 않은 현재 범위를 유지합니다.
   `replace ... => ../proxy-source`와 시험 폴더 구조에 의존하는 현재 go.mod 변경은 그대로 복사하지 않습니다.
   고정 모듈·패치를 빌드 작업 폴더에 준비하는 방식과 임시 modfile 또는 vendor 방식을 비교하여
   독립된 체크아웃에서 빌드 가능한 형태를 선택합니다. 패치 대상 버전·SHA256·적용 실패 조건을 기록합니다.
2. 실행 도구: 현재 작업 폴더 유지·명시적 샘플/프로젝트 선택·로그인·중지·제거 기능을 정리합니다.
   시험 루트 하드코딩을 제거하고 두 세션을 동시에 사용할 때 종료 시 프록시가 다른 세션에 미치는 영향을 확인합니다.
3. 공통 설정 동기화: 사용자 경로를 매개변수화하고 재적용·충돌·스킬 참조 변경을 검증합니다.
   원본과 운영 환경의 `viewMode: default`를 유지합니다.
4. 모델 메뉴: 검증된 7개 GPT 모델과 기본 272,000 컨텍스트·medium effort를 보존합니다.
   확대 컨텍스트·priority/fast 등은 자동으로 켜지 않습니다. GPT-6.1을 기본 모델로 바꿀지는 별도 결정합니다.
5. 개인용 패키지·설치 도구: 버전·소스 SHA·기준 SHA·프록시 패치·Claude/Go 버전·검증 결과를 manifest에 기록합니다.
   체크섬을 만들고 검증된 패키지를 원자적으로 선택할 수 있도록 준비합니다.
6. 문서·관리 지침: 확정된 운영 규칙을 루트 AGENTS.md에 연결합니다.
   CLI 동작이 변경되는 경우 upstream AGENTS.md 요구대로 README와 해당 landing 문서를 함께 갱신합니다.
   의존성 변경 시 THIRD_PARTY_NOTICES도 확인합니다. 사이트 실제 배포는 하지 않습니다.

현재 trial의 자격 증명·캐시·이력 전체를 작업 브랜치에 복사하지 않습니다.
기존 시험 검증은 이전 변경의 근거로 활용하되, 정식 소스·패키지 검증을 대신하지 않습니다.

## upstream 갱신 방식

`main` 동기화와 개인용 소스 갱신·설치 전환을 별도로 수행합니다.
`main`을 최신으로 옮겼다는 이유만으로 `dialects/custom`이나 설치 패키지를 갱신하지 않습니다.

1. 현재 정상 소스 태그·패키지·운영 데이터 복귀 수단을 보존합니다.
2. 필요한 변경을 확인하고 선정한 upstream SHA를 기록합니다. 향후 릴리스가 생기면 해당 릴리스도 평가합니다.
3. 그 기준에서 `dialects/sync/YYYYMMDD`를 생성하고 필요한 개인 변경만 이전합니다.
4. 프록시 의존성·인증·번역·모델 목록 변화와 기존 패치 제거 가능성을 확인하고 관련 검사를 수행합니다.
5. 검증한 내용과 이전 통합 이력을 보존하여 `dialects/custom`에 통합합니다.
   충돌·새 후속 변경이 있으면 조사·반영하고 다시 검증합니다.
6. 개인 포크에 일반 push로 보관하고 정상 태그·설치 기록에 새 소스 SHA를 고정합니다.
7. 설치 승격은 별도 검증 후 수행합니다. 실패하면 현재 정상 패키지를 계속 사용합니다.

카탈로그 갱신이 upstream에서 해결되면 개인 패치를 제거하는 것을 우선 검토합니다.
CLIProxyAPI까지 별도 포크하는 것은 동작 수정이 지속적으로 필요할 때 다시 판단합니다.
upstream 기여는 CONTRIBUTING.md의 accepted issue 절차를 따르며, 별도 요청 없이 issue·PR을 전송하지 않습니다.

## 정식 승격의 완료 기준

다음 단계에서 실행할 검사를 먼저 설명하고 승인된 범위에서 수행합니다.
필요한 도구를 자동 설치하거나 전역 셸 설정을 임의로 변경하지 않습니다.

- 독립된 소스 체크아웃에서 시험 루트 없이 패치 적용·개인용 빌드가 재현됩니다.
- 변경 영역의 Go 포맷·테스트·vet 및 기존 upstream 검사를 확인합니다.
  플랫폼 코드·대시보드·의존성 변경은 upstream의 추가 검사와 notices 규칙을 따릅니다.
- 기본 모델·7개 메뉴·medium effort·272,000 컨텍스트가 유지되고 확대 설정이 활성화되지 않습니다.
- 승인된 짧은 실제 요청으로 GPT-6.1, 도구 사용 및 변경 영향 범위의 기능을 확인합니다.
- `/context`에서 기존 사용자 지침과 스킬 16개를 인식합니다. 설정 병합을 반복해도 GPT 설정이 보존됩니다.
- 현재 프로젝트 폴더 실행·동시 세션·프록시 종료·설정 재적용·기존 명령 `claude` 보존을 확인합니다.
- 설치된 패키지의 SHA256이 검증한 패키지와 일치하고, 직전 정상 패키지로 복귀할 수 있습니다.
- OAuth·설정·이력 이전 결과를 별도로 확인하며 인증 정보는 로그에 기록하지 않습니다.

현재 프록시가 요청의 `max_tokens`를 그대로 전달하지 않는 점은 이미 확인했습니다.
설정의 출력 토큰 값이 서버 측 강제 상한을 보장한다고 설명하지 않습니다.
이를 고치는 별도 프록시 변경은 현재 이전 범위에 포함하지 않으며, 필요하면 목적·검증 범위를 별도로 정합니다.
대용량 경계 요청은 기본 승격 검사에 포함하지 않습니다.

## 설치·복귀 구조 제안

| 항목 | 제안 위치 |
| --- | --- |
| 버전별 패키지 | `~/.local/opt/claude-dialects-personal/releases/<개인버전>-<짧은-SHA>/` |
| 활성 패키지 | 같은 루트의 `current` 링크 |
| 운영 상태 | `~/.local/share/claude-dialects-personal/state/` (`DIALECT_HOME`) |
| 이전 백업·설치 기록 | `~/.local/share/claude-dialects-personal/` 하위 사용자 전용 경로 |
| 사용자 명령 | `~/.local/bin/claude-gpt` — GPT dialect 실행 |
| 기존 Claude | 기존 `claude` 경로·동작 유지 |

개인 버전은 upstream SHA를 포함한 `personal.1+eac8612` 같은 형태로 식별하고 다음 승격마다 증가시킵니다.
실제 버전 문자열은 첫 패키지 작업에서 확정합니다. 정상 소스 태그와 설치 manifest를 함께 사용합니다.

실행 파일 복귀는 `current`를 직전 정상 패키지로 연결합니다.
운영 상태·설정·이력 복원은 실행 파일 복귀와 별개이며, 문제가 확인된 대상만 백업에서 복원합니다.
첫 이전에서는 정식 경로에 데이터를 복사하고 시험 환경을 유지하되, 인증·이력을 복사한 두 환경을
동시에 운영할 때의 영향과 인증 갱신 동작을 먼저 확인합니다. 시험 도구의 제거 스크립트는 수정하지 않습니다.
정식 명령·데이터·정상 패키지 검증 후 시험 환경 제거 여부를 결정합니다.
